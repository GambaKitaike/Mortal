**日付:** 2026-07-31

選択肢を並べるだけで、**変更は行っていない**（環境そのものの変更 = 新しい実験レジームであり、

## 1. 現状の実装（一次ソース）

`libriichi/src/arena/game.rs:74-98`（`Game::poll` の局開始判定）:

```rust
// after W4
// or, after all-last
//   and, oya is not in renchan
//   and, anyone has more than 30k
if self.kyoku >= self.length + 4
    || self.kyoku >= self.length
        && !self.in_renchan
        && self.scores.iter().any(|&s| s >= 30000)
{
    self.ended = true;
```

- `length = 8`（東風なら 4）。半荘は `kyoku` 0..7 が東1〜南4
- **南4終了時に 30000 点以上の者が居なければ終わらず、`kyoku = 8` に進む**。
  場風は `bakaze = E + kyoku / 4`（`board.rs:245`）なので `kyoku 8..11` = **西1〜西4**
- 打ち切りは `kyoku >= length + 4` = **西4終了**
- 親の連荘は別条件（`game.rs:160-178`）: オーラスで親が 30000 点以上**かつトップ**なら終了、
  それ以外は連荘（`honba += 1`、`kyoku` は進まない）
- 天鳳ルール準拠であることはコード中のコメントが明示している
  （`game.rs:57-64` が天鳳のサドンデス規定を引用）

**フリー雀荘ルールでは通常、南4終了で 30000 点未満でもそのまま終局**する（西入なし）。

`analyze_west_round_impact.py`。西1局の開始直前でログを打ち切った**反実仮想**
（= 西入なしルールでの終局）を作り、challenger の3ストリームを実際の結果と比較した。
経済ロジックは `analyze_freeparlor_pnl_1v3.py` / `chip_from_log.py` をそのまま呼ぶ（複製禁止）。

### 2a. 判定への影響（現行の凍結済み判定はどれも動かない）

| 判定/参考値 | 実測の効果量 | 西入の寄与（b04 − init の差分） | 比 |
|---|---:|---:|---|
| 判定2 チップ | +0.405 枚（SE 0.231） | 約 −0.004 枚 | **効果量の 1%・SE の 2%** |
| 素点（参考） | +0.492（SE 0.762） | 約 −0.018 | SE の 2% |
| 順位点（参考） | +0.912（SE 1.187） | 約 **−0.100** | **SE の 8%** |

**⇒ 西入を消しても C/K/b04 の判定は変わらない**（最大でも順位点で 1SE の 8%）。
放銃率・和了率は局単位の指標なので、西場の局が消えても率としてはほぼ動かない。

### 2b. 測れていないこと（過小評価になりうる）

**上表は事後集計であり、方策の意思決定の変化を含まない。**
西入があると「オーラスで 30000 点に届かせる」ことに価値があり、
無ければオーラスは純粋に着順勝負になる。**オーラスの押し引き・打点選択が変わる**ため、
学習への実効はここで測った量より大きくなりうる。**方向は不明**（測るには実際にルールを
変えて run を回すしかない）。

## 3. 変更の含意（ここが裁定の本体）

1. **これは環境（報酬を生む世界）の変更であり、新しい実験レジームになる。**
   変更後に測った値は、変更前に**訓練された**方策の登録値と厳密には比較できない
   （eval だけなら同一レジームで両脚を測れるので内部妥当性は保たれる）
2. **凍結中の事前登録との衝突**: `l1_o1_submit_every_design.md` は
   **plain PPO を baseline とし、参照脚に Stage1-16000 を使う**ことを凍結した（§11）。
   Stage1-16000 は**西入ありで訓練された** checkpoint なので、
   **O1 を西入なしで訓練すると「submit_every」と「ルール変更」の2変数になる**
3. **libriichi の Rust 変更**（`CLAUDE.md`「新規 Rust 表面積は最小に」）。
   ビルド手順と import スモークが必須。`arena` 側の変更で、`state`（プレイヤー視点）や
   obs には触らないので**観測空間・ネットワークは不変**
4. **本家との分岐**: 天鳳ルール準拠から離れる。`enable_rule_based_agari_guard` のように
   **既定 OFF のフラグ**にすれば既存経路はビット不変に保てる

## 4. 選択肢

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **W1** | **config フラグ化**（例 `[env] enable_west_round`、**既定 = true = 現状**）。false で南4終了 | 既存経路がビット不変。検定でデフォルト恒等性を assert できる。いつでも A/B できる | Rust + config + 検定の3点セット（半日程度） |
| **W2** | ハード変更（西入を無条件で消す） | 実装最小 | 過去 run の再現ができなくなる。本家挙動に戻せない |
| **W3** | 当面変更しない（負債として記録） | コスト 0 | 商品ルールとの乖離が残る |

**実装エージェントの推奨: W1。** 理由は (a) `p_enrich` / `anchor_prob` / `kl_beta` と同じ
「既定 OFF で既存経路ビット不変」の前例に乗れる、(b) ルール変更の効果自体を
**単一変数実験として測れる**（西入あり/なしの対照）、(c) 商品プリセット
（`product_gaps_design_notes.md` G3 の雀荘ごとのウマオカ・チップ）と同じ枠に収まる。

## 5. 実施順の提案（**裁定事項**）

GPU は1系統で、直近の枠は L1 O1 が押さえている。順序の候補:

| 順 | 案 | 影響 |
|---|---|---|
| **S1（推奨）** | **O1 を現行ルール（西入あり）で先に走らせる** → その後に W1 を実装し、以後の run を西入なしへ | O1 の単一変数が保たれる。ルール変更は L1 O3 以降の regime 切り替え点になる |
| S2 | W1 を先に実装し、O1 から西入なしで走らせる | O1 の baseline（Stage1-16000 = 西入ありで訓練）との比較が2変数になる。参照脚を n=800 で測り直す予定（§7 の凍結事項）なので **eval 側は揃うが訓練側が揃わない** |
| S3 | W1 を実装するが**既定 true のまま**（フラグだけ用意して当面 OFF にしない） | 実装だけ先行して意思決定を後送りできる。O1 への影響ゼロ |

**S1 か S3 なら O1 の事前登録（凍結済み）に一切触らずに済む。**
S2 を採る場合は O1 の凍結記録に amendment（baseline の再定義）が要る。
