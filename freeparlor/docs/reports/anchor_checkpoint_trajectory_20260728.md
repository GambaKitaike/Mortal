## 2. 読み取れること

### 2a. 判定1・判定2 を両立する checkpoint は（この粒度では）存在しない

**全 checkpoint で放銃 z ≥ 2.5**。「早期停止すれば基礎を保ったままチップを取れる」という
仮説は、4000 step 粒度では**支持されない**。§1 の測定は判定を変えないが、
**商用採否（0b 議題1）の「中間 checkpoint を配備する」案は成立しにくい**ことを示す。

### 2b. 劣化もチップ獲得も **step 2000 までに完了している**（step2000 追測により確定）

**step2000 の追測（2026-07-28、§3-3 の宿題を消化）で、区間はさらに狭まった。**
init → step2000（**全体の 12.5%**）で:

| 量 | Arm K | Arm C |
|---|---|---|
| 放銃 | 11.85 → **13.89**（z=+3.91） | 11.85 → **14.29**（z=+4.53） |
| 降りの中断率 | 23.78 → **31.78** | 23.78 → **37.95** |
| 立直和了 割合 | 54.32 → **81.24** | 54.32 → **89.10** |
| チップ | +0.035 → **+2.85SE（全 checkpoint 中の最大）** | +0.035 → **+2.17SE** |

**チップは step2000 が両腕とも最大**（K +2.85 / C +2.17）で、以後 14000 step かけても
超えない。**立直和了割合も step2000 で既に 81〜89% に達している**（init 54.32%）。
すなわち**方策の性格変化は最初の 2000 step でほぼ完了**しており、
残り 14000 step は「維持（K）か喪失（C）か」の期間でしかない。

### 2b-2. 旧記述（step4000 時点の観察。step2000 追測により上書きされた）

init → step4000 の1区間で:

| 量 | Arm K | Arm C |
|---|---|---|
| 放銃 | +1.63pp（z=+3.12） | +1.93pp（z=+3.58） |
| 降りの中断率 | 23.78 → **32.17**（+8.4pp） | 23.78 → **41.28**（+17.5pp） |
| 立直和了 割合 | 54.32 → **78.26** | 54.32 → **84.84** |
| チップ | +0.035 → **+0.511（+2.09SE）** | +0.035 → **+0.527（+2.09SE）** |

**チップ獲得は両腕とも step4000 で +2.09SE と完全に一致**しており、以後 12000 step を
かけても K は +2.18SE までしか伸びない。**16000 step のうち最初の 1/4 で勝負がついている。**

### 2c. C と K の分岐は初期ジャンプの**後**に起きる

step2000/4000 時点では両腕は近い（チップ K +2.85 / C +2.17、step4000 では +2.09 で一致）。
そこから **放銃 z の向きが逆**になる — **K は 3.91 → 2.51 と回復し、C は 4.53 → 6.57 と悪化**:

- **Arm C**: 降りの中断率が 41.28 → 45.06 → 47.32 → **49.29** と**単調悪化**し、
  チップは +2.09 → +1.12 → +1.66 → **+0.45** と**獲得した分を失っていく**
- **Arm K**: 降りの中断率 32.17 → 33.98 → 36.38 → **33.75** と**横ばい**、
  チップも +2.09 → +2.30 → +2.48 → **+2.18** で**維持**

→ **KL アンカーの効能は「初期劣化を防ぐこと」ではなく「その後のドリフトを止めること」**
である。この区別は判定文書からは読み取れず、本軌跡で初めて分かった。

**Arm C の失敗の正体も変わる**: 「チップを獲得できなかった」のではなく
**「step4000 で獲得したものを 12000 step かけて失った」**。§2c の単調悪化と整合する。

## 3. 含意（裁定は Gamba / 0b）

1. **kl_beta=0.4 再走（§6a）の問い方が変わる。** 「β を上げれば放銃劣化が閾値内に入るか」
   ではなく、**「β を上げれば step4000 までの初期ジャンプを抑えられるか」**が本質。
   現行 β=0.1 は初期ジャンプを素通しし、以後のドリフトだけを止めている
2. **L1（最適化衛生）の優先度が上がる。** 損傷が最初の 4000 step に集中しているなら、
   staleness（lag 1–2 = 50–100 optimizer step）や clip 0.20–0.33 といった
   **最適化の初期挙動**が関与している可能性がある（`ppo_optimization_health_20260725.md`）。
   ただし**因果は未検証**であり、本軌跡はそれを示していない
3. ~~測定粒度の限界~~ **step2000 を追測して消化（§2b）。** 損傷も獲得も
   **最初の 2000 step（全体の 12.5%）でほぼ完了**していることが確定した。
   次の粒度（step 0–2000 の内部）は checkpoint が存在しないため、
   測るには `save_every` を下げた新規 run が要る
