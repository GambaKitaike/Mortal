## 1. 何を検定したか

L1 診断（2026-07-25）は 8 run 共通の構造的事実を3つ出した:

1. `minibatch_size = 512` は一度も効いていない（1 optimizer step = 1 半荘の full-batch × 4 epochs）
2. **バッチ到着時点（epoch 1）で既に clip_fraction ≈ 0.20–0.33**（= 収集経験の約2割が
   恒常的に勾配に寄与していない）
3. 4 epochs は trust region 占有をほぼ動かさない（epoch1→epoch4 の差 −0.0008〜−0.0032）

ただし**因果は未検証**だった。L1 系列はその因果を検定する対照実験で、
**改善策としてではなく**登録した（0b 裁定 §2 の留保をそのまま引き継いだ）。

| arm | 単一変数 | 検定した命題 |
|---|---|---|
| **O1** | `submit_every` 50 → 10 | H(O1): off-policy staleness の削減は基礎劣化を小さくする |
| **O3** | `ppo_epochs` 4 → 1 | H(O3): 1 バッチあたりの最適化量の削減は基礎劣化を小さくする |

判定条件は **anchor 系列（C / K / b04）と同一の計測器・同一 seed・同一 n=800** で、
横並び比較できるように凍結した。

## 2. 結果

| | 判定1 放銃差 z<2 | 判定2 チップ ≥1SE | baseline 比 Δ−Δ_ref | 合算 |
|---|---:|---:|---:|---:|
| 参照 plain PPO（`=50`, `epochs=4`） | +2.876pp（z=+5.43） | +0.630（+2.63SE） | — | +2.809（+0.99SE） |
| **O1**（`submit_every=10`） | +2.635pp（**z=+4.91**）✗ | +0.381（**+1.62SE**）○ | −0.241pp（−0.32 z, n.s.） | −2.128（−0.76SE） |
| **O3**（`ppo_epochs=1`） | +1.620pp（**z=+3.13**）✗ | **+0.639（+2.77SE）**○ | **−1.256pp（−1.70 z, n.s.）** | **+5.237（+1.89SE）** |

- **判定1 は両 arm とも不成立**。**L1 では基礎劣化（放銃）を閾値以下に戻せなかった**
- **判定2 は両 arm とも成立**。O3 は **+2.77SE で anchor 系列を含めた全 arm で最大**
- **O3 の合算（素点+順位点+チップ）は +5.237 千点/半荘で init を上回った**。
  **全ストリームが + 方向**になったのは本プロジェクトで初
- O3 の avg_rank は −0.036（改善方向・n.s.）、和了率の劣化も z=−1.41 で有意でない

### 2a. 事前登録した交絡の識別（O3 §3a）— **交絡は支配していなかった**

O3 は「trust region の衛生」と「総勾配更新 64,000 → 16,000」を同時に動かすため、
「劣化が小さいのは単に方策が動いていないだけ」という対立仮説があった。
**結果を見る前に**操作的定義を凍結してあった（init からの行動シフトが参照の 1/2 未満なら交絡が支配）:

| | O3 のシフト | 参照のシフト | 参照比 | 判定 |
|---|---:|---:|---:|---|
| 立直率 | +12.97pp | +14.66pp | **88.5%** | 1/2 超 |
| 副露率 | −7.81pp | −10.86pp | **71.9%** | 1/2 超 |

⇒ **O3 は参照とほぼ同程度に方策を動かしたうえで、劣化が小さく経済が良かった。**

## 3. 系列の中心的知見: **clip を支配していたのは staleness ではなく 1 バッチあたりの最適化量**

| | staleness（バッチ単位） | ×epochs = **経過 optimizer 更新数** | clip@epoch1 |
|---|---:|---:|---:|
| 参照（`=50`, `epochs=4`） | 91.5 | **366** | 0.2019 |
| **O1**（`=10`, `epochs=4`） | **73.0**（−20%） | **292**（−20%） | 0.2046（**変化なし**） |
| **O3**（`=50`, `epochs=1`） | 90.7（不変） | **91**（**−75%**） | **0.0521（−75%）** |

- O1 は**バッチ単位の staleness を −21% にしたのに clip はまったく動かなかった**
- O3 は**バッチ単位の staleness を据え置いたまま clip を −75% にした**
- 両者を統一的に説明するのは「**clip は staleness 窓の間に経過した optimizer 更新数に
  比例する**」という読み。O1 の −20% は run 間ばらつきに埋もれ、O3 の −75% は明白に出た

⇒ **L1 診断の事実2（バッチ到着時点で既に clip ≈ 0.2）の主因を特定した。**
「データが古いから」ではなく「**古い間にパラメータを 4 倍動かしているから**」である。
これは因果の問いに対する L1 系列の最大の収穫で、判定1 が落ちたこととは独立に残る。

### 3a. 副次の実測（設計書の予測の検証）

- **O1 §1a**: 量子化成分 24.5 → 4.5（理論値どおり）、transit 68.5 は不変
  ⇒ 「`submit_every` が動かせるのは staleness の約 26% だけ」という事前分解が完走データで確認された
- **O3 §1c**: trainer 計算を 63–65% 削っても wall clock は 24.4h（O1 27.6h / anchor_k 24.6h）
  ⇒ 「wall clock は client 律速」という予測が的中。**epoch を減らしても学習は速くならない**
- **O3 §1a**: epoch 2–4 はバッチ内で方策をほとんど動かさない（ratio_mean 変化 ≤0.0005、
  ratio_std 約 1%）。5 run で符号一致 ⇒ L1 診断の事実3 を再確認

## 5. 閉幕の理由と持ち越し

### 閉幕する理由

- **判定1 が両 arm で不成立**。L1 の主要な2本の足はどちらも基礎劣化を止められなかった
- **再走規定なし**（O1 §3a / O3 §3c）。`submit_every` に自明な次の値は無く、
  `ppo_epochs` は 1 が下限
- **2 seed 目は判定1 ○ のときのみ**（凍結済み）。したがって走らせない
- 残る L1 候補 O2（複数半荘の batch 束ね）は**判定窓を消費半荘数で定義し直す必要**があり、
  別設計（バックログへ戻す）

### 持ち越す資産

1. **`ppo_epochs=1` は次以降の既定候補**（下記 §6 の裁定事項）
2. **計測器**: `analyze_staleness_decomposition.py`（staleness の分解 + 機械ゲート）、
   `gate_l1_o3_epochs.py`、**`analyze_yakuhai_retention.py`（新設）**
3. **運用の負債返済**: バックログ4（完走 run の偽トレースバック）を根治し run-validation 済み
   （`backlog4_respawn_fix_20260802.md`）。**鎖が2本あった**ことの記録を含む
4. **eval 運用の教訓**: `eval_grp_baseline_1v3.py` を直接叩くときは `GRP_BASELINE_CKPT` を
   必ず明示する（既定値が DQN 期の `steps=0` ファイル。O1 の参照脚が一度これで壊れた）
5. **参照脚 Δ放銃_ref = +2.876pp（n=800、判定と同一計測器）** — 以後の cross-run 比較に使える

1. **`ppo_epochs=1` を以後の既定にするか。**

## 7. 次の軸（0b 裁定 §2 の残り）

0b 裁定の順序は **L1 →（候補2）敵対的搾取者訓練 →（候補1）oracle 蒸留**。
加えて 2026-07-31 の西入裁定で **W1（config フラグ化）+ S1（既定を西入なしへ）** が
「L1 O1 を現行ルールで走らせた後」という条件つきで承認済みであり、**その条件は満たされた**。

**順序の論点**: S1 はゲームのルールを変えるので、**先に S1 をやらないと、
以後の run はすべて「西入あり」で訓練された init・参照脚と比較され続ける**。
逆に S1 を先にやると、init と参照脚の再測（eval のみ・GPU 数時間）が要る。
