## 4. 読み — 何が言えて何が言えないか

### 4a. 言えること

**立直シフトは頑健に速い。** 立直和了割合は step200 で既に 63%、step600 で 78% に達し、
以後 2000 まで横ばい。init 54.29% からの上昇は step600 時点で **z=+10.86**。
`anchor_checkpoint_trajectory_20260728.md` §2b の「方策の性格変化は最初の 2000 step で
ほぼ完了」は、**行動シフトの側については本 run でも支持される**（しかも
2000 ではなく **600 step** でほぼ完了している）。

**checkpoint 間のばらつきが大きい。** 放銃 z は 200 step 刻みで
−0.45 〜 +3.47 を行き来する（11.75% 〜 14.64% = 2.9pp = 4 SE 幅）。
隣接 checkpoint 間でこれだけ動くということは、
**「ある step の方策の放銃率」を1点1回の eval で測ると推定が粗い**。

### 4b. 言えないこと（**過大解釈の禁止**）

- **「放銃劣化は起きない」とは言えない。** step16000 の判定値
  （Arm K z=+2.51、n=800）は別途確定しており、本 run はそれに触れない
- **「Arm K の step2000 が外れ値だった」とも断定できない。** n=2 run の比較で、
  どちらが典型かを決める材料は無い。言えるのは
  **「同一 config で 2 run 取ったら step2000 近傍の放銃劣化は一致しなかった」**まで
- 本 run は **n=400・step1900**（Arm K は n=800・step2000）。SE と step が
  完全には揃っていない

### 4c. 設計 §6 の「読み」表への照合

設計書 §6 は事前に4つの形と読みを列挙していた。実測は:

| 事前に列挙した形 | 実測 |
|---|---|
| 放銃劣化が step 200–400 で大半完了 | **該当せず**（z は step1400 まで積み上がらない） |
| 放銃劣化が 0–2000 で線形 | **該当せず**（単調でなく往復する） |
| 立直シフトが放銃劣化に**先行** | **該当**（立直は step600 で完了、放銃 z のピークは step1400） |
| 放銃劣化が立直シフトに先行 | 該当せず |

→ 事前登録の枠内で読むなら「**立直シフトが先行し、放銃劣化はその後に、
しかも不安定に現れる**」。ただし §4b のとおり本 run 単独では因果を主張しない。

## 6. 含意（裁定は Gamba / 0b）

1. **`anchor_checkpoint_trajectory_20260728.md` の位置づけを下げる必要がある。**
   同書は「損傷もチップ獲得も最初の 2000 step で完了」を
   `session_handover_20260728.md` §1b で「本セッション最大の発見」としているが、
   その根拠のうち**放銃劣化の部分は n=1 run**であり、本 run で再現しなかった。
   立直シフトの部分は再現した
2. **今後 checkpoint 単位の量を比較するときは、run 間ばらつきを見積もる必要がある。**
   本 run が示したのは「隣接 checkpoint で 4 SE 幅に振れる」ことで、
   単一 checkpoint × 単一 eval の点推定は思ったより粗い
3. **§6a の kl_beta=0.4 再走の問い方が再び変わる。** `session_handover_20260728.md` §2 は
   §1b を根拠に「初期 2000 step のジャンプを抑えられるか」を問いにしていたが、
   **そのジャンプ自体の再現性が怪しい**。再走するなら問いは元の
   「判定窓で閾値内に入るか」に戻すか、あるいは**同一 config の複数 run で
   ばらつきを測る**方向になる（後者は事前登録が別途要る）
