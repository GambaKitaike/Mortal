## 1. 実験設計の方針 — seed の使い方（**全実験に掛かる標準規律**）

`early_damage_probe_result_20260729.md` §9 が「同一 config の run 間ばらつきが
効果量と同程度」であることを示したのを受けた決定。

> **新規アイデアはすべて 1 seed で走らせる。**
> **事前登録の判定を満たしたものだけ 2 seed 目を走らせる。**
> **2 seed とも同じ方向なら「採用候補」。**
> **2 seed で食い違ったものは「効果不確実」として保留する。**

これは逐次スクリーニング設計であり、GPU 予算を倍にせずに再現性を担保する。
1本目で判定を落ちたものに2本目を使わないので、**外れの候補にコストを払わない**。

### 1a. 実装上の注意（**次に登録する実験で確定させること**）

- **「同じ方向」の定義を、2 seed 目を走らせる前に固定すること。** 判定が
  複数条件（例 anchor 系列の判定1/判定2）で構成される場合、「同じ方向」が
  (a) 同じ象限に入ること なのか (b) 主判定の符号が一致すること なのかで
  結論が変わる。**結果を見てから決めると post-hoc goalpost になる**
  - 実装エージェントの推奨: **主判定の符号一致 + 有意性は問わない**を既定にする
    （2本目は再現性の確認であって独立の判定ではないため）。ただし採否は Gamba
- 2 seed 目は**新規 run dir・同一 config・seed のみ変更**（`1 branch = 1 variable` の
  精神。ただし訓練側の seed は現状 config で明示制御していないので、
  **何をもって「別 seed」とするかの操作的定義も登録時に決める**）
- 「効果不確実」で保留した候補は**捨てない**。バックログに残し、
  他の証拠が増えたときに再評価する

## 3. 議題ごとの裁定

### 議題1 — 立直マキシマリズムの商用採否: **否決（条件つき）**

> 「今のところ否決。立直以前の問題として、まだまだ牌理やポンテン・チーテン取らずも
> よくあるので、出すつもりはない。**せめてここが直ってから**」

**この否決は定量指標と一致している**（`policy_quality_metrics_20260728.md`）:

| 所見 | 対応する測定 |
|---|---|
| ポンテン・チーテン取らず | **有役テンパイ機会の見送り率** init 84.09% → **K 90.51%（z=+5.14）** / C 96.20%（z=+11.11） |
| 牌理 | 向聴を外した率 **C 0.72%→2.55%（z=+22.27）**。ただし **Arm K は n.s.** で init 水準を保存 |
| （併記）押し引き | 降りの中断率 init 23.78% → K 33.75%（z=+12.83）/ C 49.29% |

→ **再検討の条件が明示された**: 「鳴き判断（特に有役テンパイ機会の取りこぼし）と
牌理が init 水準まで戻ること」。これは**測定可能な条件**なので、
今後の run はこの2指標を判定の参考副読に含めるとよい（判定条件そのものではない）。

**注意**: Arm K は牌理については既に init 水準を保っている（z n.s.）。
残っているのは**鳴き判断と押し引き**であり、この2つは KL アンカーでも止まらなかった。

### 議題2 — 経済定数変更: **今はしない**

> 「現行ルールではするつもりはない。もちろん**ルール自体が変わることによって
> 順位点やチップ価値を変えて学習することはあるかもしれない**」

→ 経済プリセット run（`product_gaps_design_notes.md` G3）は**現行ルールの範囲では起票しない**。
ルール変更を伴う商品プリセット（雀荘ごとのウマオカ・チップ）を実装する段になったら
改めて検討する。**G3 の設計（Rust 変更ゼロで実装可能という調査結果）は保全**する。

### 議題3 — 敵対的搾取者訓練: **やる（L1 の O1→O3 の後）**

> 「これは行うつもり。L1 の O1⇒O3 の後にやりたい。**ラベルデータなしでの学習は
> 正直どれが良さげか全くわからないし、もしかしたら全部やることになるかもしれない**」

→ `teacherfree_training_candidates.md` §3（候補2）の粗設計を事前登録へ格上げする。
残件は **§3e の2点**（判定条件 = §3d の「標的固有のレート差上乗せ」/ 搾取者の init を
標的のコピーにするか mortal init にするか）。**どちらも発進前に登録が要る。**

**「全部やることになるかもしれない」という見立ては記録に値する** — 候補の優劣が
事前に決まらないなら、§1 の seed 方針（1 seed でスクリーニング）が特に効く。

### 議題4 — Stage2b（解凍実験）の再評価: **保留**

内容の再掲（次に読む人のため）: Stage2 は `p_enrich=1.0` の**赤濃縮配牌**で育てた run。
その checkpoint を**自然分布で fine-tune し直せるか**を見る実験。
Stage2 判定で**配備税**（濃縮分布育ちの方策は自然分布への配備で avg_rank 2.4750→2.7050、
≈2.9SE の有意な損失）が見つかったため、「収束済み方策を別の分布へ適応させられるか」
という問いの商用価値が上がった、というのが起票の経緯（バックログ3）。

→ **保留**。議題2 が「現行ルールでは経済を動かさない」となった以上、
分布シフト適応の実用需要も当面は薄い。

### 議題5 — ライセンス・データ権利の分界: **保留（困っている論点として明記）**

> 「正直困っている。anchor の Arm K はある程度有効であることはわかりそうだが、
> **結果これがライセンスの問題で使えないのではどうしようもない**」

→ **保留**。ただしこれは「後で考える」ではなく**未解決のリスクとして明示**されている。
`robust_selfplay_ppo_design.md` §5c の整理を再掲しておく:

- Arm K が得たのは**部分的な**保護で、それは**強い人間譜由来の参照点**による
- 牌譜非依存アンカー（A1 解析的 aux loss / A2 ルールベース蒸留 / A3 scratch 中間 ckpt）で
  同等以上が出るかは**論理的に導けない = 別の実験**（16k run 1本の未計上コスト）
- **持ち越せるのは機構の知見と配管**（アンカーは config のパス指定で差し替え可能）。
  持ち越せないのは産出された重み

**次に動かすなら**: 法務判断（天鳳規約・AGPL の解釈）は専門家確認が前提で、
技術側でできるのは A1–A3 の実現可能性を測ることだけ。議題3/6 の後になる。

### 議題6 — 次世代訓練方式の選択: **議題3 と同じ = 搾取者訓練が先、その後 oracle 蒸留**

> 「議題3 と同様の結論で、敵対的搾取訓練について。**そのあとは候補1の oracle 蒸留**
> あたりをやりたい」

→ 順序が確定した:

```
L1 O1 → L1 O3 → 候補2（敵対的搾取者）→ 候補1（oracle 蒸留 / 自己教師あり補助タスク）
```

候補1 の部品は**このセッションで大半が揃った**（`session_handover_20260729.md` §1）:
`shanten.py` の形別分解・受け入れの形別分解・1手先の受け入れ、`yaku.py`、
`hand_value.py`（確定打点）。いずれも libriichi 実測で検証済みで、
**補助タスクのラベル生成にそのまま使える**。残る大物は oracle テンソル
（相手の待ち・危険牌）の配線で、これは Rust 変更ゼロ・全 call site が
`is_oracle=False` で休眠中（`teacherfree_training_candidates.md` §2f）。
