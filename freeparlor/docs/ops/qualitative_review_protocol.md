# 定性レビュー（レンズ4）実施プロトコル

**ステータス: 制定（2026-07-25、Gamba 裁定）。** eval バッテリーの標準脚として、
run 完走時に必ず実施する。

**位置づけ: 判定非関与。** 事前登録された判定条件（各設計書の判定節）は一切変更せず、
定性所見をいかなる判定にも使わない。よって凍結中の設計書（例 `anchored_ppo_design.md` §6）に
抵触しない。所見の用途は**次の実験を決める材料**と、**定量指標の見落とし検出**である。

---

## 1. なぜ標準脚にするのか（2件の実例）

自動集計が全て正常に通っていたのに、人が牌譜を見て初めて分かったことが2件ある。

1. **基礎技能劣化の兆候は 2026-07-16 に出ていた。** Stage3-16000 の定性レビュー
   （`qualitative_expert_review_stage3_20260716.md`）が「鳴いた後は下手」「降りの規律が
   崩壊気味（放銃率上昇と整合）」「カン判断が異常」を記録。しかし DRCA 第2枠は 07-21 に発進し、
   基礎劣化の診断が形になったのは 07-25。**所見から方針転換まで9日、次の GPU 投入まで5日の
   遅延**があった。所見を放銃率という定量指標に突き合わせる段が抜けていたのが原因。
2. **解釈そのものの訂正。** DRCA 第1枠 ΔQ̂ 極値24件の全件目視
   （`qualitative_expert_review_drca_frame1_20260722.md` §4）が、分布の裾支配と
   「同一山ゆえ結果論は K=8 で消えない」を指摘し、監督側の主説明（方策の降りの雑さ）を撤回させた。
   集計スクリプトは正しく、数値も正しく、**解釈が間違っていた**。

## 2. いつ実施するか

```
run 完走 → レンズ1（argmax eval バッテリー）
         → レンズ2（grp_baseline 1v3・配備税チェック）
         → レンズ3（メタ対決 probe・ミラー較正脚）
         → ★レンズ4（本書）★
         → 判定の起草
```

**判定より前に行うこと。** 後追いにすると、上記1件目のように「所見はあったが次の実験が
先に走っていた」が再発する。GPU は不要（牌譜は既に出ている）ため、レンズ1–3 の完了後すぐ着手できる。

## 3. 手順

### (1) 対象牌譜の特定

- argmax eval の自己対戦牌譜: run dir の `test_play/`
  — **注意**: `clear_log_dir` 仕様により、バッテリー中に**最後に走った checkpoint** の牌譜しか
  残らない。どの checkpoint のものかは実行 ORDER と mtime で必ず確定してから読むこと
  （2026-07-16 に実際に確定作業が必要になった）。
- 1v3 対戦牌譜: `eval_*` 系の出力ディレクトリ。
- 診断 run（DRCA 等）の場合は、集計結果から極値ケースを機械抽出したテーブルを併用する。

### (2) HTML 化

```bash
conda run -n mortal python freeparlor/scripts/mjai_log_to_html.py <牌譜 or ディレクトリ> --out-dir /home/gamba/mahjong/runs/viewer_out/
```

一覧 `index.html` も生成される。生成物はローカル成果物（commit 対象外）。

### (3) レビュー範囲（最低ライン）

- 自己対戦（最終 checkpoint）**2半荘以上**
- 1v3 **1半荘以上**
- 診断 run の場合は極値 **上下各10件以上**（第1枠の前例は負12+正12の24件・全件目視）

観点は固定しない（人の目の価値は事前に列挙できない異常の検出にある）。ただし過去の所見と
同じ軸——**鳴き後のサブゲームの質 / 降りの規律 / カン判断 / 役の一貫性**——は最低限見る。

### (4) 所見 → 定量指標への突き合わせ【必須】

**この段が本プロトコルの中核。** 所見をそのまま置かず、必ず対応する定量指標を1つ以上探して
突き合わせ、結果を記録する。

| 所見の例 | 突き合わせる指標 |
|---|---|
| 降りが雑・危険牌を押す | 放銃率（`analyze_fundamentals_1v3.py`、半荘クラスタ SE 付き） |
| 鳴いた後が下手 | 副露時の和了率・平均打点、副露率との乖離 |
| カン判断が異常 | カン回数と局収支、該当局の抽出 |
| 好機を取りこぼす | 該当クラスの反実仮想（DRCA 系の層別） |

**乖離があれば、その場で診断タスクを起票する**（所見だけで終わらせない）。
指標が存在しない所見は「未計測」と明記して残す — それ自体が次の計装候補になる。

### (5) 記録

`freeparlor/docs/reports/qualitative_expert_review_<対象>_<日付>.md` に記録する。
書式は既存3本に倣う（`qualitative_expert_review_20260715.md` /
`_stage3_20260716.md` / `_drca_frame1_20260722.md`）。冒頭に必ず
「**判定非関与**」の位置づけを明記し、(4) の突き合わせ結果と、起票した診断タスクを含める。

## 4. 出力の扱いと既知の限界

- 所見は判定に使わない。ただし**次の実験の優先順位を決める材料としては一級**として扱う。
- レビュアは Gamba（麻雀上級者）。監督側は所見を数値へ翻訳する役で、**所見の否定・上書きをしない**
  （第1枠 §4 の前例: 専門家の反論で監督側の主説明が撤回された）。
- 反実仮想レビューの外的妥当性には限界がある — probe は方策条件付きであり、
  「その方策が後で下手を打つ」ことが分岐の評価に混入する（同 §4）。
