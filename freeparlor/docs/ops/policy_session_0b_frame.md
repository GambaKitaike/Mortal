## 1. 確定済みの事実ベース（DRCA 結果に依存しない）

- **探索ラダー3段全て不成立**: Stage1 純探索（0.236×）→ Stage2 分布介入（0.185× +
  配備税）→ Stage3 報酬介入（anneal 後 1.066×・有意減衰）。立直マキシマリズムは
  経路によらない頑健な均衡
- **正典反鳴き勾配は定量再現**: 判定窓 raw advantage は call_taken +0.018 vs
  declined +0.522（Stage3）≈ Stage1（+0.012 / +0.524）
- **機会費用ギャップ ~5.5–5.9 チップが支配項**。副次確認: 鳴き局正典収支は改善方向
  （チップ/局 −0.95 → −0.63 → −0.33）だが損益分岐に届かず
- **配備税は介入形態依存**: 分布介入（Stage2）は有意、anneal 内蔵の報酬介入
  （Stage3）はゼロ → 「介入は anneal とセット」制約は対照実験済み
- **メタ対決**: 残留鳴きは立直メタで負債（Stage3-16000 vs Stage1-16000 チップ
  −0.675±0.236 ≈ −2.9SE）
- **DRCA パイロット**: ΔQ̂ = −0.4575 ± 1.5882 千点（n=50、n.s.）。本測定 N=485 で
  95%CI 半幅 ≤1.0 千点まで絞られる
- **§5a-1b 適用済み**: セット(b)×init 脱落。解釈 C は
  「Stage3-16000 vs Stage1-16000（セット(b)）」の1本で判定

## 2. DRCA 判定 × 議題の分岐（討議用シナリオ）

主判定はセット(a)×主レンズの ΔQ̄（4 checkpoint）+ contrast 2/3（§5a-2）。
解釈 A–D の条件文言は `drca_probe_design.md` §4（凍結）が正。

### シナリオ A — 内在的機会費用（全 checkpoint で ΔQ̄ < 0 有意、(b) で正側移動なし）

- 技術的含意: 方策は正しく損を学んでいる。phase 2（DRCA 訓練組み込み）は
  正当化されない（§4 A の凍結文言どおり）
- 議題1: 立直マキシマリズムは**当該経済設定での正解**。採否は「鳴かない瑕疵」では
  なく絶対競技力・商品性で判断する土俵に移る
- 議題2: 「鳴きのある AI を見たい」なら**経済定数変更が唯一の残存経路**
  （感度実験系の設計へ）
- 議題3: 独立に価値あり（均衡の頑健性検査として）

### シナリオ B — credit assignment 失敗（ΔQ̄ > 0 有意 かつ π(鳴き|可能∧赤保持) < 0.31）

- 技術的含意: 学習器が「得」を見えていない。phase 2 の検討解禁（§7）
- 議題1: 商用化は保留寄り（伸び代が残っている）。phase 2 の成否を先に見る選択肢
- 議題2: 定数変更の前に学習器側の修理が先
- 議題3: 価値上昇（搾取可能性が実在する示唆）

### シナリオ C — 競技力ギャップ（(b) で Stage3-16000 が Stage1-16000 より有意に正側）

- 技術的含意: 鳴きスキルを付ければ得になる。**C∧B は最高介入価値の象限**（§4）
- 議題1/2/3: B に準じるが、介入手段はスキル訓練（カリキュラム等）が第一候補になる

### シナリオ D — レンズ間符号割れ（主・副レンズが両方有意で逆符号）

- 技術的含意: 報酬設計誤指定の疑い → `reward_design_teacherfree.md` 再訪を起票
  （§4 D）。**議題1–3 は全て凍結し再監査を優先**

### シナリオ N — 全て n.s.（0 近傍・検出力は充足）

- 技術的含意: 赤保持鳴きの機会費用 ≈ 0（鳴いても鳴かなくても大差ない）
- 議題1: 「鳴かない損」も「鳴く得」もない → 純粋に商品性（見た目の打牌選択）の
  問題に還元。ε-greedy 的な演出混合等の非学習的解も土俵に入る
- 議題2/3: 動機は弱まる

## 5. 商品性要件ヒアリング結果（2026-07-24、Gamba 回答・裁定非関与）

§3 の最大の未充足だった「商品性の要件定義」を Gamba ヒアリングで埋めた記録。

### 5.1 確定した6軸

| 軸 | Gamba 回答 |
|---|---|
| 商品形態 | **検討/サジェストツール（メイン）＋ AI 対戦機能**。対戦→牌譜→解析/サジェストのループが商品コア（雀荘ルール用の麻雀ゲームが希少なため対戦自体も価値）。強さ測定のため Gamba が AI と実戦することもこの対戦機能に乗る（2026-07-24 補足で明確化） |
| 最優先の性質 | **絶対的な強さ**（打ち筋は結果が伴えば不問） |
| 「ほぼ鳴かない立直特化」の許容 | **見た目としては許容**。ただし採用の前提は「本当に最強である確証」。**現状の立直特化が最強だとは考えていない**（現行学習系での均衡にすぎない）。実験・検証で最強と確認できて初めてその方向で商品化（2026-07-24 補足で明確化） |
| 強さの合否基準 | **人間（Gamba/専門家）との実戦**（収支・打牌妥当性の主観判定） |
| サジェスト出力形式 | **上位N手 + 評価値**（複数候補を評価値付きで提示） |
| 経済プリセット軸 | **鳴き祝儀/面前祝儀の違い・ウマオカ表・チップ**（複数選択） |

### 5.2 §2 シナリオ・議題への含意

1. **商品形態はサジェスト（メイン）＋ AI 対戦の二枚看板。** 対戦機能は一級（雀荘ルール
   ゲームの希少性そのものが価値、かつ対戦牌譜が解析/サジェストの入力源になる）。
   したがって「AI がどう打つか」も牌譜生成源として意味を持つ。ただし**商品の評価軸は
   依然「助言の正しさ＋強さ」で、打ち筋の見た目の自然さは低優先（打牌不問）は不変**。
   シナリオ N の「ε-greedy 的演出混合」やメタ対決レンズ（7d）の商品的重みが低い点は
   変わらない（対戦は "自然に見せる" ためではなく牌譜と実戦検証のために置く）。
2. **議題1 の裁定は DRCA 結果に強く依存する（当初の "A/N なら強さ一点に収束" は
   後退・訂正）。** Gamba は**現状の立直特化が最強だとは考えておらず**、本当に最強かを
   実験・検証で確かめてから商品化する方針。よって「鳴かない見た目の瑕疵」論点は消えるが、
   **「本当に最強か」の実証論点が残る**。DRCA の位置づけ: シナリオ A（鳴いても損）は
   「この経済設定で立直特化が正解」の重要証拠、B/C は「まだ最強でない＝伸び代」の証拠。
   探索ラダー3段全滅は "現行学習系での均衡" を示すが "真に最強" の証明ではない点と整合。
   この「最強性を反証しに行く」動機は議題3（敵対的搾取者訓練＝立直特化を搾取できるかの
   テスト）の価値も引き上げる。
3. **DRCA が診断計測器から "商品の中核クレーム" に格上げされる。** サジェストツールが
   「鳴くな」と助言するとき、その正しさは ΔQ̂（鳴きの反実仮想価値）が実際に負かに直接
   依存する。したがって集計 ΔQ̄ の符号だけでなく **層別（chi/pon/kan・向聴・巡目・
   点況）が "どの局面で鳴けと薦めるか" の商品仕様に直結** → これまで判定非関与の
   exploratory 扱いだった層別が、判定後の商品設計では一級市民になる。
   **注意: これは DRCA の凍結解釈条件（`drca_probe_design.md` §5a/§4）を変更しない。**
   判定の解釈は凍結のまま。ここで言うのは "判定後の商品設計での利用価値" の話。
   frame1 の裾支配（負の裾=本物の手壊し / 正の裾に取りこぼし候補）が、この文脈では
   "鳴けと言うべき局面クラス" の設計材料になる。
4. **経済プリセットが第一級ロードマップに昇格。** 定数変更（議題2）は "鳴く AI を出す
   苦肉の策" ではなく商品の軸そのもの。祝儀構造の事実関係（2026-07-24 第2次補足で
   確定・旧記述を訂正）: 面前祝儀ルールでも**役満は鳴き和了でもチップ対象**、
   裏・一発は構造的に立直専用 → **面前/鳴き祝儀軸の実効差分は赤のみ**。現行
   `chip_base`（赤+裏+一発+役満×5）は赤を面前条件なしで払うため**現行は赤について
   既に鳴き祝儀相当**であり、この軸で鳴き誘因を現行より足す余地はない（面前祝儀
   プリセットは鳴き手の赤チップを取り上げる=ギャップ拡大方向のみ）。旧記述
   「鳴き祝儀の追加が機会費用ギャップを直接補助する最標的レバー」は**誤りにつき撤回**。
   ギャップを縮める経済レバーは chip_value・赤枚数等の別軸。面前/鳴き軸の価値は
   商品再現プリセット + 逆方向の対照実験（赤チップ=現行の残存鳴き誘因説の検証）に
   整理し直し（`product_gaps_design_notes.md` §3.1 訂正版が正）。
   立直特化が祝儀構造のアーティファクトではなく本物の均衡である点（§1 と整合）は不変。

### 6.3 議題1 との依存関係

議題1（立直マキシマリズムの商用採否）の前提は §5.1 の「本当に最強である確証」だが、
**議題5 が「最強でも製品に持ち込めない重みに依存している」と裁定した場合、
議題1 の採否判断の意味が変わる**（採用対象が方策ではなく「方策を再現する手順」になる）。
§4 の運び順（1→2→3→4→5）はこの依存を承知の上での提案であり、順序は Gamba 裁定。

### 6.4 anchor 系列は無駄になるのか（2026-07-28、Gamba 質問への回答の記録）

**結論: ならない。ただし「研究計測器として扱う」場合に限る。**

- **持ち越せる**: 機構の知見（**引き戻しは pool より損失側（KL）に置くほうが効く**という
  単一変数で確定した順序関係）、配管（アンカーは `anchor_checkpoint` /
  `kl_ref_checkpoint` の**config パス指定**なので差し替え可能。`train_ppo.py:107` は
  checkpoint パスを受け取ってロードするだけで中身を問わない）、判定書式（n=800 等）
- **持ち越せない**: 産出された重み。ただし**これは anchor 系列に始まった話ではない**
  — Stage1〜3 の全 checkpoint も同一 init から warm-start しており元から同じ制約下。
  anchor が変えたのは種類ではなく程度（init が t=0 の一点 → 16000 step 全区間の常駐）
- **本当のリスクは2つ**: (i) 成功を「出荷可能」と読み違えること、
  (ii) アンカーの強さ自体が有効成分である可能性（§6.2-2 の ⚠）。
  **K は判定1 を落としている**ので (ii) のマージンは無い
- **C/K は無駄ではなかった**: 「アンカーは効くのか / どこに置くと効くのか」を知らないまま
  牌譜非依存アンカーを設計すると、失敗時に「機構が悪いのか参照点が弱いのか」を分離できない。
  C/K はその分離のための前提であり、実際に「pool より損失側」を単一変数で確定させた

詳細は `../design/robust_selfplay_ppo_design.md` §5b / §5c。
